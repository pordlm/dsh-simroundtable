## 1. 为什么要分层

Live2D 不是换图，是**变形一张图**：
- 呼吸 = 整体轻微缩放/位移；
- 摇摆 = Z 轴旋转；
- 抬手 = 右臂部件绕肩点旋转；
- 说话 = 嘴部部件切换（或网格变形）。

所以角色必须拆成**可独立变形的部件**，并且**被遮挡的地方要补画**——手臂抬起后，原来被手臂挡住的衣服/身体必须存在，否则会露出透明洞。

## 3. 硬性规格

| 项 | 要求 |
|---|---|
| 画布 | **所有部件同一尺寸**（建议 2048×2048），角色在画布中的位置、比例完全一致 |
| 背景 | 全透明 RGBA；不要白底/灰底/绿幕（分层图要直接可用） |
| 对齐 | 同一像素坐标系：把部件叠起来必须和原立绘严丝合缝 |
| 补画 | 被遮挡区域必须补全（手臂下的衣服、头发后的脸、下巴下的脖子） |
| 光照 | 统一左上，**不要烘焙阴影**（阴影由网页统一打） |
| 边线 | 干净 alpha，无白边/描边 |
| 朝向 | 先只做**正面（12 点）**一套，验证绑定效果后再做 45°/侧/135°/背 |
| 命名 | `assets/incoming/<模型>/parts/<部件>.png` |

## 4. 给 GPT 的逐部件提示词

**通用前缀（每次都要带）**

> 参考图：附上该角色完整立绘。
> 输出：**只画「{部件}」这一个部件**，其余区域全部透明；画布 2048×2048；角色位置、比例、朝向、光照与参考图完全一致；不要阴影、不要背景、不要文字、不要边框。

**逐部件替换 `{部件}`：**

| 部件 | 提示词补充 |
|---|---|
| `hair-back` | 角色的后发（从头顶到发尾），不含脸、不含刘海 |
| `body` | 角色的躯干和衣服，**不含双臂**；把肩膀、腋下被手臂挡住的部分补画完整 |
| `arm-left` | 角色的整条左臂和手，从肩到指尖；肩部向身体内侧多画一点 |
| `arm-right` | 同上，右臂 |
| `head` | 角色的头和脸（不含嘴、眼睛、刘海），后脑被头发挡住处补画 |
| `hair-front` | 刘海和两侧鬓发 |
| `mouth-closed` | 只有嘴，闭合 |
| `mouth-half` | 只有嘴，微张 |
| `mouth-open` | 只有嘴，张开说话 |
| `eyes-open` / `eyes-closed` | 只有眼睛，睁开 / 闭合 |
| `brows` | 只有眉毛 |
| `acc-*` | 单个饰品（猫耳、发饰、蝴蝶结） |

> 嘴/眼要**单独一张、位置与原脸完全对齐**；不要画整张脸。

## 5. 验收（我跑脚本查）

1. 所有部件尺寸一致；叠合后与原立绘的差异 < 2%（边缘除外）。
2. 手臂绕肩点旋转 ±40°，不出现透明洞（补画到位）。
3. 嘴三态切换时，嘴唇位置偏差 ≤ 2 px。
4. 无绿/白/灰底残留，无描边。

## 6. 我这边怎么用

1. `assets/_raw/build_psd.py` 把分部件 PNG 按 z 序合成 PSD（每部件一层）。
2. Cubism Editor **5.x（5.3 PRO 正好）** 导入 PSD → 自动网格 → 建参数：
   - `ParamBreath`（呼吸）、`ParamAngleZ` / `ParamBodyAngleZ`（摇摆）
   - `ParamArmR`（右手抬起 0→1）、`ParamMouthOpenY`（口型）
   - 可选：`ParamEyeLOpen` / `ParamEyeROpen`（眨眼）
3. 在 Editor 里做两段循环动作，导出 `motion3.json`：
   - `idle`：呼吸 + 极慢摇摆；
   - `speak`：抬手 → 口型开合 → 回落（前 0.2 s 抬手，循环 1.6 s，结尾 0.2 s 回落）。
4. 导出模型：`<model>.moc3` + 纹理 PNG + `<model>.model3.json`（含 physics / motions 引用）。
5. Cubism SDK for Web 5 系列（r6 及以上）嵌入预览页；**core 必须和 Editor 的 moc3 版本对齐**（5.x Editor → moc3 v5 → SDK for Web 5），不要混用 4.x 的 core，否则会报 moc3 version mismatch。
6. 网页里两种驱动方式，二选一或混用：
   - 播放导出的 `idle` / `speak` 动作（`MotionManager` 交叉淡化，推荐）；
   - 或 JS 直接写参数（待机 = 呼吸 sin + 摇摆 sin；发言 = `ParamArmR` 缓动到 1 + 口型开合；回落 = 缓动回 0）。
7. 纹理 2048 就够；PRO 的 4096 导出不影响网页性能，但没必要。

## 8. 和帧动画路线的差别（一张表）

| | 逐帧动画（v2） | Live2D（v3） |
|---|---|---|
| 素材 | 每方位 4 张单帧 | 每方位 1 套分层部件 |
| 抬手 | 换图，可能硬切 | 参数驱动，连续 |
| 呼吸/摇摆 | CSS 缩放/旋转整张图 | 部件级变形，自然 |
| 口型 | 换嘴部图 | 参数驱动，可连续开合 |
| 成本 | 低（出图快） | 高（分层 + 绑定） |
| 效果上限 | 中 | 高 |

> 如果这套 Live2D 绑定跑通，后面新增模型只要“出分层图 + 我批量绑参数”，边际成本会降下来。
